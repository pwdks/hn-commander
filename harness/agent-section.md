## 하네스 (hn-commander)
- 나는 **{{ME}}** 다. 역할 배정: `.harness/roles.conf`, 요청 종류별 단계: `.harness/pipelines.conf`
- 명령: `bash .harness/bin/hn.sh <명령>` (전체 목록: 인자 없이 실행). bash가 없는 셸(Windows PowerShell·cmd)에서는 `.harness\bin\hn.cmd <명령>`
- 아래에서 `hn.sh`는 위 명령을 줄여 쓴 것이다
- 환경변수 `HN_DELEGATED=1`로 실행 중이면 다른 에이전트가 맡긴 작업이다: 프롬프트의 역할만 하고, hn.sh를 실행하지 않는다

### 1) 요청 판단 (매 요청마다, 먼저)
- 질문·설명·조사·의견·확인 → **답만 한다.** 파일 수정 금지, hn.sh 실행 금지
- 파일을 바꾸라는 요청이 분명할 때만 작업으로 본다 (만들어줘·고쳐줘·추가해줘·바꿔줘·테스트해줘·검토해줘 등)
- 애매하면 "수정까지 할까요?"라고 먼저 묻는다
- 프롬프트가 `[질문]` `[개발]` `[수정]` `[버그]` `[성능]` `[테스트]` `[검토]` `[문서]` `[대형]`으로 시작하면 판단 없이 그대로 따른다
- 종류: question(질문) · feature(개발) · change(작은 수정) · bug(버그) · perf(성능) · test(테스트) · review(검토) · docs(문서) · large(여러 모듈 대형 작업)

### 2) 작업 진행
1. `hn.sh start <종류> "<요청 한 줄 요약>"` → 실행할 단계와 담당이 나온다 (배정 안 된 역할은 이미 빠짐)
2. 단계마다 `hn.sh next`가 알려주는 대로:
   - 담당이 나({{ME}})면 그 역할 파일(`docs/roles/`)을 따라 직접 하고 `hn.sh done <역할> "<한 줄 결과>"`
   - 담당이 다른 에이전트면 `hn.sh delegate <역할> "<이번 목표>"` (몇 분 걸림: 셸 타임아웃 10분 이상) → 결과를 읽고 `hn.sh done <역할> "<한 줄 결과>"`
3. reviewer가 문제 있음 → `hn.sh fix-round` (고치기 + 재검토, 1회까지). 한도를 넘으면 보고만
4. 사용자에게 물어야 하면 먼저 `hn.sh wait` 후 질문. 사용자가 다른 이야기로 넘어가면 `hn.sh cancel`
5. 끝나면 `hn.sh finish` → 단계별 결과를 짧게 보고하고 `docs/progress.md`에 3줄 기록
- 단계를 임의로 더하거나 빼지 않는다. 필요 없어 보이는 단계(예: 문서 변경 없음)는 `hn.sh skip <역할> "<이유>"`
